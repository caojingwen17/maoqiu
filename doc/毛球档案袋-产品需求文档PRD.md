### v1.3 变更摘要

以代码实现为准全量同步（前端 20 个页面 / 18 个组件，云函数 36 个 action + reminderCron 5 分钟 / diaryCron 凌晨 00:30 双定时器），主要变更：

- **删除宠物功能移除**：前端无任何删除入口，只保留归档——首页「显示已归档」开关（归档置底 + 弱化 + tag）、详情页只读、长按归档宠物仅「取消归档」（6/7 章重写）
- **囤货扣减改显式选择**：feed/deworm/medication 三类记录表单内「从囤货扣减·选填」chip，默认不扣，选中才带 inventoryId 由后端校验扣减；旧的「自动消耗/自动扣库存」描述全部清除（8.2/10.2）
- **「附近医院」功能移除**：代码中不存在，工具箱收敛为 3 个纯前端工具、无聚合页（13）
- **记录 data 结构对齐**：实际为 `items[{label,value}]` 展示数组 + 派生字段（nextDate/cycleDays/amount/courseDays/medicationTimes 等）；records 增加 requestId 幂等与 inventoryId 溯源（4.2）
- **首页待办交互对齐**：点击行直跳记录表单（带预填）、左滑出「完成/忽略」两个操作、≥2 条出现「忽略全部」（6.3）
- **快捷记录面板**：swiper 两页 8+10 共 18 类，无「更多」格、无页码文案（6.5）
- **提醒中心对齐**：进行中仅展示 7 天窗口、无左滑/服药合并行/「查看更早」；新建预设事项 12 项、分周期/一次性两类、通知范围无附加文案、提前天数固定 7、延后固定 3 天（云端上限 30 天）（9.1）
- **统计页对齐**：无全局宠物 chips，三卡独立选择器；热力图格子点击（非长按）（11）
- **记账页对齐**：整预算卡可点、无齿轮、无左滑删除；预算单位为**元**（8.3/4.5）
- **家庭协作对齐**：邀请 7 天过期（family.lastInviteAt）、kickedFrom 仅服务端写入（客户端仅可清空）、退出/被移出数据不回迁、解散确认仅前端比对名称（4.6/15）
- **§4.7 索引改为引用** `cloudfunctions/pawlog/INDEXES.md`（按代码实际查询整理的权威清单）
- 明确标注当前版本不存在的功能：表单返回放弃确认、就医照片槽位引导、体重 ±20% 提示、喂食计划、记录乐观锁、服药打卡 checkins 等

## 1. 产品概述

### 1.1 产品定位

一款面向养宠人士的**宠物信息记录与管理工具**。帮助用户系统化管理宠物档案、健康医疗、喂养生活、花销账目，并通过智能提醒避免遗忘疫苗、驱虫等关键事项。

### 1.2 一句话 slogan

「每只毛孩子，都值得一份完整的档案。」

### 1.3 目标用户

- **主要人群**：25~40 岁城市养宠青年，养 1~3 只猫/狗
- **次要人群**：多宠家庭、宠物繁育人、救助站志愿者（多宠管理刚需）
- **用户痛点**：
  1. 疫苗/驱虫时间靠脑子记，经常忘
  2. 病历、化验单散落各处，就诊时说不清病史
  3. 养宠花销没概念，月底一算吓一跳
  4. 换手机后记录全丢

### 1.4 设计原则

1. **工具优先**：所有功能围绕「记录—提醒—查询」闭环，不做 Feed、不做社区
2. **三步可达**：任何记录操作从首页出发不超过 3 步
3. **多宠平等**：所有功能默认支持多宠物，数据结构从第一天就按多宠设计
4. **数据属于用户**：数据归属用户家庭空间；备份/恢复/导出不纳入当前版本
5. **克制打扰**：提醒宁缺毋滥，用户可完全掌控

### 1.5 竞品参考（差异化）

- 宠日常 / 小佩宠物：绑硬件或社区，臃肿 → 我们纯工具、轻量
- 通用备忘录/Excel：不懂宠物业务 → 我们内置疫苗/驱虫周期自动滚动提醒、多物种档案差异字段等宠物领域知识

## 2. 名词定义

| 名词 | 定义 |
|---|---|
| 宠物档案 | 一只宠物的基础信息实体，系统的核心数据单元 |
| 记录 | 挂在某只宠物名下的任一条数据（体重/疫苗/花销等统称） |
| 时间线 | 某只宠物所有记录按时间倒序的聚合视图 |
| 提醒 | 由系统或用户创建的待办事项，分周期型和一次性 |
| 待办 | 已到期（含逾期）的提醒；提醒 Tab「进行中」另展示未来 7 天窗口 |
| 囤货（库存） | 猫粮、猫砂、驱虫药等家里囤的消耗品管理单元：余量 + 保质期 + 记录时显式选择联动扣减 |
| 快捷记录 | 首页弹出的「记一笔」快速录入面板（swiper 两页 18 类，3 列网格） |

## 3. 信息架构

### 3.1 页面地图

```
首页（宠物卡片墙，Tab 1）
├── 宠物详情页（Tab：时间线 / 相册 / 日记本）

├── 记录表单页（快捷记录面板唤起，18 类共用一页）
├── 体重表单页（大数字输入，独立页）
├── 记录详情页
└── 邀请落地页（家庭加入）
提醒管理页（Tab 2）
└── 新建/编辑提醒页（共用一页）
统计页（Tab 3）
我的（Tab 4）
├── 记账页
├── 囤货列表页
│   ├── 入库表单页（入库/编辑共用一页）
│   └── 物品详情页
├── 工具箱（无聚合页，分组直接列三行）
│   ├── 年龄换算器
│   ├── 喂食量计算器
│   └── 安全食物查询
├── 家庭成员管理页
└── 归档宠物管理页
```

> 共 20 个页面（见 `miniprogram/app.json`）。早期原型中的健康模块页、体重详情页、相册页、工具箱聚合页、附近医院页均不存在：体重曲线在统计页体重卡内，相册为详情页 Tab。

### 3.2 底部 Tab 结构（4 个 Tab）

| Tab | 页面 | 说明 |
|---|---|---|
| 宠物 | 首页（卡片墙） | 核心入口 |
| **提醒** | 提醒管理页 | **独立一级模块**：进行中/已完成、新建护理提醒、周期管理 |
| 统计 | 统计页 | 数据图表 |
| 我的 | 设置页 | 家庭、囤货、记账、工具箱、归档 |

> 注意：全产品（含 Tab 图标、列表、文案、推送消息）严禁使用 emoji，Tab 图标使用矢量线性图标（详见设计语言文档 v2.2 第 9 章）。

> 评审决策：提醒管理由「隐藏入口」升级为独立 Tab（第 2 位），因为"避免遗忘"是产品核心价值；**日历模块整体砍掉**——记录的"时间维度回看"由时间线（按日分组）和统计页覆盖，独立日历属冗余视图。提醒的辅助入口保留：首页「今日待办」卡标题行右侧「全部提醒 ›」（顶部栏无铃铛图标）。记账、囤货、工具箱不做独立 Tab，从我的页面进入。

### 4.2 `records` 记录集合（所有类型记录统一集合）

| 字段 | 类型 | 说明 |
|---|---|---|
| _openid | string | 云开发自动写入（记录人），数据可见性以 familyId 为准 |
| familyId | string | 所属家庭空间 ID |
| createdBy | string | 记录人 openid，时间线展示「谁记的」 |
| createdByName | string | 记录人昵称快照；**读取时（list/get）会被 settings.familyNick 实时覆盖**，保证用户后补称呼后历史记录也显示称呼 |
| petId | string | 关联宠物（家庭级记录如囤货入库花销可为空） |
| type | string | 枚举：weight/vaccine/deworm/medical/medication/surgery/feed/water/snack/groom/poop/vomit/heat/expense/walk/litter/milestone/custom/daily |
| date | number | 记录发生时间（不得晚于今天） |
| data | object | 各类型扩展字段（见下） |
| photos | array | 云存储 fileID 数组，≤9 |
| videos | array | 云存储 fileID 数组（仅日常类型，与 photos 合计 ≤9，单个 ≤ 10MB） |
| note | string | 备注，≤500 字 |
| requestId | string | 客户端生成的幂等键，重复提交按 familyId+requestId 去重返回原记录 |
| inventoryId | string | 显式选择的囤货扣减目标（仅 create 生效，update 忽略；仅 feed/deworm/medication 允许，见 10.2） |
| createAt / updateAt | number | 时间戳 |

**`data` 的实际结构：** 表单字段全量保留为 `items: [{label, value}]`（详情页逐条展示），再按类型附带派生字段供提醒/账单逻辑使用；服务端字段袋校验 `weight`（0<v≤500）、`amount`/`price`（≥0）、`nextDate`（正数时间戳），未知字段宽松保留。

| type | data 内容 |
|---|---|
| weight | {weight: number(kg)}（独立体重表单页直接写入，不走 items） |
| vaccine | items（疫苗 / 针次 / 医院 / 批号）+ nextDate（下次日期，选填） |
| deworm | items（类型：体外/体内/内外同驱；药品） |
| medical | items（手术名称·选填 / 医院 / 症状 / 诊断）+ amount（费用，选填，计入账单） |
| medication | items（药品 / 剂量 / 频次）+ courseDays（疗程 1~90 天，开提醒必填）+ medicationTimes + medicationReminder |
| surgery | items（手术名称 / 医院）+ amount（费用，选填，计入账单） |
| feed | items（餐次：早餐/午餐/晚餐/加餐；食物；克数；状态：全部吃完/有剩余/没怎么吃） |
| expense | items（分类：粮食/零食/医疗/用品/玩具/美容/寄养/保险/其他；明细）+ amount（元） |
| poop | items（性状：正常/软便/稀便/便秘/带血；颜色：棕色/黄色/发黑/发绿/灰白） |
| groom | items（项目多选：洗澡/剪指甲/梳毛/刷牙/洁耳/擦眼睛/美容；门店；金额计入账单） |
| vomit | items（呕吐物：未消化食物/毛球/黄水/白沫/带血；次数：1 次/2 次/3 次及以上） |
| walk | items（时长，分钟；只记时长不记距离，见 8.2） |
| water | items（水量，ml） |
| snack | items（零食；数量：少量/适量/吃多了） |
| heat | items（开始日期；表现多选：叫春/乱尿/烦躁/食欲差） |
| milestone | items（标题；日期） |
| custom | items（标题；内容） |
| daily | 无结构化字段（仅 note + photos + videos；videos 为 cloud:// fileID 数组，客户端限制单个 ≤ 10MB，微信无同步视频内容检测接口故云端不做内容校验） |

| completedAt / completedBy / completedByName | number / string / string | 完成时间与完成人快照（界面暂不展示完成人） |
| ignoredAt / ignoredBy | number / string | 「忽略本次」的时间与操作人 |

提醒相关约束：`remindAt` 必须为正数时间戳且不允许早于当前时间 1 小时以上（schema 校验）；同宠物同 category 的**记录派生**周期提醒（当前仅疫苗）只保留一条 active（新记录触发更新而非新增，用户手动创建的同类提醒不被接管）。

提醒相关的微信发送记录使用 `messageSubscriptions`、`messageGrants`、`messageDeliveries` 三个集合：授权按 OpenID 独立记录；每次客户端返回 `accept` 幂等增加一条可用额度；发送时事务抢占最早可用额度，每个提醒发生时间和接收成员只发送一次（`deliveryKey` 唯一索引幂等），发送成功才消费额度；无额度时投递进入 `waiting_grant`，24 小时内获得新额度可迟发补救，超时判死信；sweeper 每轮清理 30 天前的终态投递/额度并回滚卡死超 1 小时的 reserved 额度。

| 集合 | 关键字段 |
|---|---|
| `messageSubscriptions` | `_openid`、`templateId`、`lastResult`、`persistentState`、`acceptedCount`、`sentCount`、`lastRequestAt`、`updateAt` |
| `messageGrants` | `_openid`、`templateId`、`requestId`、`source`、`status`（available/reserved/consumed/invalid）、`persistentChoice`、`reservedBy`、`createAt`、`consumedAt` |
| `messageDeliveries` | `deliveryKey`（提醒 ID+发生时间+成员）、`familyId`、`reminderId`、`recipientOpenid`、`occurrenceAt`、`templateId`、`status`（sending/sent/waiting_grant/failed）、`attempts`、`errorCode`、`sentAt`、`createAt`、`updateAt` |

### 4.7 索引与安全规则

- **共享带来的权限变更**：默认「仅创建者可读写」规则不再适用。所有数据读写改走**云函数中转**（云函数内校验：请求人 openid 是否存在于目标 familyId 的 members 中，不在则拒绝——`family.join` / `family.preview` 例外），客户端不直连数据库
- 写入经 `schema.js` 白名单 + 类型校验闸门：不认识的字段一律拒绝；各集合可写字段以 4.1~4.6 为准
- 所有集合保留 `_openid` 字段用于审计与「我创建的数据」筛选
- **索引清单**：以 `cloudfunctions/pawlog/INDEXES.md` 为权威清单（按 modules/ 实际 where + orderBy 整理，共 24 条组合索引：records 6 / reminders 8 / diaries 3 / messageGrants 2 / messageDeliveries 3 / pets 2）。其中 `reminders(status + remindAt asc)` 是 reminderCron 全量扫描的硬性依赖，缺索引会报错

### 5.3 加载与错误

- 首屏加载：全屏 `paw-loading` 爪印动效（全端统一），不转圈不骨架屏
- 列表加载：触底或点「加载更多」分页加载；时间线/相册每页 30 条，日记每页 20 篇
- 提交失败：Toast「网络开小差了，请重试」，表单数据**保留不清空**
- 云函数请求失败自动重试 1 次（`services/api.js`），无显式客户端超时；云函数侧 timeout 配置 60 秒（含 AI 日记生成），模型单次请求默认 8 秒（`DIARY_LLM_TIMEOUT_MS`，钳制 3~15 秒）并最多重试 1 次
- **性能约定**：客户端在每次调用顶层携带缓存的 `familyId`（`app.globalData`，启动时预热；KICKED/FORBIDDEN 时清缓存自愈），云函数命中快路径跳过 resolveFamily 的 settings 查询，成员校验仍权威执行；`home.aggregate` 的 9 条数据库查询全部并行（Promise.all）；提醒页通过 `reminder.list status=all` 单次调用返回进行中 + 近 30 天已完成 + 宠物名册；统计页通过 `stats.summary` 单次调用返回三卡数据 + 宠物名册（三卡各自独立选宠物：wtPetId/expPetId/heatPetId，体重卡未选时云端默认第一只未归档宠物并回传 wtPetId）；囤货列表走轻量 `inventory.list` 单查询；`record.get` 直接返回 petName 与最新记录人称呼
- **加载动效统一**：依赖云端数据的首屏统一用 `paw-loading` 组件（爪印描边动画 + 随机宠物冷知识）做全屏加载态，数据返回前不渲染空态，避免「以为没数据」（含首页，骨架屏已废弃）
- 图片上传失败：单张失败静默跳过（console 告警），不阻塞记录保存，其余张正常上传；当前无重传角标

### 5.4 权限与隐私

- 微信订阅消息：接入一次性模板「待办事项提醒」（`dx8E4xROB3HiNg9Pj0OTqsLUE5WP0Ja5Mo_cFvFmlPA`）。首次授权必须由用户明确点击触发；用户可在微信弹窗中勾选「总是保持以上选择，不再询问」。授权被拒绝或额度不足时，仍保留小程序内待办、红点和提醒中心，不阻断核心功能。页面加载、`onShow`、后台任务和原生 Tab 切换不申请授权。

### 5.4.1 内容安全（运营规范 §5.18 / §10.2）

所有 UGC 文本与图片在云端写入前统一经微信内容安全接口校验（`modules/sec.js`，云调用免鉴权，无密钥落客户端）：

- 文本 `security.msgSecCheck`（version 2，必传 openid）：scene=1（资料）用于昵称/家庭内称呼/宠物名/品种/性格标签；scene=4（社交日志）用于记录备注与 `data.items` 填写值、提醒标题/备注、囤货物品名
- 图片 `security.imgSecCheck`：宠物头像（`pet.create/update`，仅头像变更时）、记录照片（`record.create` 全量 / `record.update` 仅新增张）、用户头像（`settings.update`），均为「下载云存储 fileID → buffer 送检」
- 判定：`suggest` 为 `risky`/`review` 或 errCode 87014 视为违规，抛 `CONTENT_RISKY`（文案「内容/图片包含违规信息，请修改后重试」），前端各保存入口 toast 原文
- 检测接口自身故障时 fail-closed，抛 `SEC_CHECK_FAIL`「内容安全检测失败，请稍后重试」，违规内容不落库
- 云函数 `config.json` 的 `permissions.openapi` 需声明 `security.msgSecCheck`、`security.imgSecCheck`，部署后生效

### 5.5 小程序内提醒与微信订阅消息

提醒中心、首页待办和红点始终可用。微信订阅消息作为增强渠道，在提醒发生时间前 30 分钟内尝试发送（发生时刻过后不再首发），每条提醒每位成员最多一条，不发送 22:00 补催。全体家庭成员和仅自己由提醒级 `notifyScope` 控制；家庭成员必须分别授权。云函数通过 `cloud.openapi.subscribeMessage.send` 发送，不在小程序端保存密钥。模板字段映射：thing1=「宠物名 · 提醒标题」（截 20 字）、time2=到期时间、thing4=备注（截 20 字或按分类兜底文案）。

云函数环境变量：`REMINDER_SUBSCRIBE_TEMPLATE_ID`（默认使用当前模板 ID）和 `REMINDER_MINIPROGRAM_STATE`（默认 `formal`，体验阶段可切 `trial`）。定时器 `reminderCron` 每 5 分钟执行（每轮三件事：窗口内提醒发送，全量扫描分页上限 1000 条；waiting_grant 迟发重试；sweeper 死信/卡死额度清理），和日记定时器分开分流。

首次引导文案仅说明「开启后微信会在事项时间提醒；如不想重复确认，可勾选总是保持以上选择，不再询问」，不使用奖励、强制勾选或阻断业务流程。用户长期允许后，在创建/保存/完成/延后/忽略提醒，以及记录、宠物、囤货的保存类点击中静默补充一次性额度；不在无关页面切换中调用授权接口。

**宠物 AI 日记生成：**

- 定时器 `diaryCron` 在 `Asia/Shanghai` 0~2 点的 30/40/50 分触发（`0 30,40,50 0,1,2 * * * *`）：**00:30 首次生成**前一天日记，失败任务在窗口内最多重试 2 次（00:40/00:50），超限停留 `failed` 不对用户展示；任务按 `diaryKey` 幂等创建，窗口内重复运行不会重复生成，窗口外（3 点以后）直接跳过。
- 每只未归档宠物每天独立进行一次 50% 概率判定；判定结果写入 `diaries.decision`，重试不重新抽签。
- 无论当天有无记录都允许生成；无记录时只能写陪伴、等待和想念，不得编造具体事件。
- 模型未配置、开关关闭、输出非法或接口超时，均不生成首页提示，不影响其他业务。
- 日记输入中的每条事件带有 `actor` 执行者称呼：取该记录创建者在「我的-家庭内称呼」中填写的 `settings.familyNick`，填什么用什么，未填写统一为「主人」（不使用微信昵称快照）。模型应按 actor 叙述实际执行者，不把“谁记录”写成事件本身。
- 日记为只读内容。用户进入详情页日记本 Tab 后，将该成员截至最新日期的日记加入 `readBy`，家庭成员之间互不影响。

**固定提示词版本：** `diaryPromptV12`。日记是宠物自己的第一人称内心独白，核心要求是「像动物写的，不像人写的」：允许牛头不对马嘴、毫无逻辑、突然换话题、句子说一半、拟声词和少量乱码式嘟囔；禁止通顺优美的完整段落、文章结构、散文镜头和大人式抒情。写法上要求模型先读完当天所有事件，挑印象最深的一两件翻来覆去地想，其余一句带过或不提，禁止按时间顺序逐条复述；允许围绕真实事件展开荒唐的想象和疑问（如“泡泡跑去哪里了”“我是不是变成泡泡猫了”），但想象必须锚在真实事件上，不得新造不存在的物品、人物或情节。`events` 是外界事实的唯一来源（当天全部类型记录，备注与明细值都会传入，上限 50 条）。多样性控制：输入附带该宠物最近 5 篇日记标题（recentTitles，要求标题/开头/角度不雷同）与随机注意力种子（focusSeed，12 个感官/情绪焦点随机抽取，与事件冲突时以事件为准）；禁止「今天……」固定开头。只能复述事件摘要明确写出的动作、地点、物品和对话，不能根据常识补全主人或家人的行为；例如写了“妈妈带我去医院”，不能扩写成“妈妈摸我的头、夸我勇敢”，除非这些动作也出现在输入中。没有相关事实时，只能写宠物自己的等待、想念、身体小反应和当下感受，不得用主人行为、室内场景或新活动凑字数。正文和标题禁止使用“你/您”等第二人称。提及照顾者时使用用户在「我的-家庭内称呼」填写的自定义称呼（`settings.familyNick`），未填写统一使用“主人”。性格标签只隐性影响节奏、观察角度和用词，不得反复自称“我是个吃货/我很安静”，也不得为体现性格编造食物或活动。要求 80～180 字、无 emoji/Markdown、只使用输入事实，并禁止医学诊断、危险建议、愧疚或控制性表达。模型输出必须通过 JSON、长度、禁用词和第一人称校验。

### 5.6 危险操作分级防护

| 操作 | 防护级别 |
|---|---|
| 删除记录 | 普通确认弹层（「删除后无法恢复，家庭成员的时间线中也会同步消失」；联动后果见 8.1） |
| 解散家庭空间 | 输入名称确认（输入框预填占位提示名称、实时比对，匹配才点亮按钮；云端再校验仅创建者可解散） |
| 归档宠物 | 普通确认弹窗（可逆，随时取消归档） |

> 当前版本**无删除宠物入口**（前端无任何入口；云函数 `pet.remove` 保留级联删除能力，仅创建者可调，未暴露给页面）。囤货物品删除为左滑二次确认。

### 6.2 宠物卡片

**展示内容（按优先级）：**
- 头像（无头像显示爪印图标占位）
- 名字 + 性别图标（♂蓝 / ♀粉）
- 品种、年龄（无出生日期显示「生日未填写」）
- 最新体重（`4.2 kg`）
- 最近事项一行（`宠物 meta`：该宠物最近一条待办标题；有未读 AI 日记时优先显示「新日记 · 点开看看」，前缀心形/铃铛线性图标）

**交互逻辑：**

| 手势 | 行为 |
|---|---|
| 点击卡片 | 跳转宠物详情页（默认落在「时间线」Tab） |
| 点击卡片右上角「+」（归档卡无此按钮） | 弹出快捷记录面板，**已预选该宠物** |
| 长按卡片 | 底部弹层。未归档：编辑资料 / 上移一位 / 下移一位 / 归档（归档有确认弹窗）；已归档：**仅「取消归档」一个操作** |
| 上移/下移一位 | 与相邻宠物交换 order（两次 update 提交） |

**边界处理：**
- 仅 1 只宠物：单列大卡布局，头像更大，额外展示物种、到家天数、性格标签和最近事项；多宠使用紧凑双列卡片
- 宠物一次全量加载，卡片墙随内容滚动，不分页
- **归档宠物**：默认不出现在首页；打开「显示已归档」开关后置底展示（弱化透明度 + 「已归档」tag，无快捷「+」按钮），可点进详情页（只读），也可在「我的 → 归档宠物」中查看与恢复
- 页面在宠物卡片下方展示轻提示「长按宠物卡片，可编辑资料、排序或归档」，避免长按能力不可发现
- 有未读 AI 日记时，卡片最近事项行优先展示「新日记 · 点开看看」，点击直接进入该宠物详情页的日记本 Tab；查看后仅当前成员的提示消失

### 6.3 全局待办区

**数据来源：** 聚合家庭所有宠物 `status=active` 且 `remindAt` 早于今天结束（即已到期，含逾期）的提醒，按 `remindAt` 升序，云端扫描上限 50 条。

**展示规则：**
- 每条显示：宠物头像缩略 + 「宠物名 · 标题」+ 时间状态 pill（`今天` / `已逾期 N 天` 红色等），整行即热区
- 标题行右侧：「忽略全部」（待办 ≥2 条时出现）+「全部提醒 ›」（跳提醒 Tab）
- 无待办时卡内显示「今天一切安好 · 所有待办已完成」（常驻，不自动收起）

**主操作：**
1. **点击待办行** → 直接跳转对应记录表单并预填（疫苗预填疫苗名 `v`、洗护预填项目 `item`；补货类跳囤货页并高亮该物品）；携带 `reminderId`，保存后联动完成原提醒（疫苗除外，由云端按新周期自动重排）
2. **左滑待办行** → 两个操作：「完成」（周期提醒推进到下一周期，一次性提醒标记 done）/「忽略」（周期提醒推进到下一次，一次性提醒移出待办但不记入已完成）。「延后 3 天」在提醒页的单条操作面板中提供，首页待办不再提供
3. 「忽略全部」→ 确认弹窗（「忽略后今日待办将全部清空，提醒本身仍会按周期继续」）后并发逐条忽略，Toast 汇总成功/失败条数

**「延后」逻辑：** remindAt += 3 天，不改变周期（只影响本次）；云端封顶 30 天。

> 当前版本待办区**无右滑手势**（右滑完成/延后未实现）。

### 6.4 统计速览横幅

3 张卡：
1. **本月花销**：`¥326.50`，点击跳记账页
2. **本周打卡**：近 7 天记录条数（`N 次`，与统计页打卡热力同口径——任意类型记录每笔记 1 次），点击跳统计页
3. **体重变化**：全家庭最新一条体重 vs 同宠物上一条的差值（`毛毛 ↑0.3kg`），点击跳体重表单页

### 6.5 快捷记录面板

**唤起方式：** 首页浮动「+」按钮 / 卡片右上角「+」按钮。

**面板内容（swiper 左右滑动翻两页，3 列网格，每页 9 格共 18 格）：**
- 第一页（9 类）：体重｜喂食｜日常｜疫苗｜驱虫｜洗护｜花销｜遛狗｜铲屎
- 第二页（9 类）：就医｜便便｜用药｜呕吐｜饮水｜零食｜发情｜里程碑｜自定义
- 手术不单独占格，作为就医的一种场景记录（就医表单含手术名称/医院/费用字段）；历史 surgery 记录仍在时间线与「健康」分组筛选中正常展示
- 翻页：swiper 横向滑动或点击底部两个圆点指示器；**无「更多」格、无页码提示文案**；美容归入洗护（groom 项目含洗澡/剪指甲/梳毛/刷牙/洁耳/美容）
- 「体重」跳独立体重表单页（大数字键盘），其余 17 类跳通用记录表单页
- 「日常」类型：面向"随手拍"场景，表单仅 文字（选填）+ 照片/视频（合计最多 9 个，单个视频 ≤ 10MB、≤ 60 秒，至少一项非空），无任何结构化字段，3 秒可完成一笔；时间线中备注与照片/视频内联展示，点击进入详情可编辑/删除

**交互逻辑：**
- 面板头部为宠物选择 chips（头像+名字，**始终不含已归档宠物**，单宠也显示一个 chip）：从卡片「+」唤起默认选中该宠物；从浮动「+」唤起默认选中第一只未归档宠物
- 面板为半屏弹层，点击空白处收起
- 无任何宠物时点类型 → 收起面板并跳新增宠物页

### 6.6 新手引导（评审决策：已移除）

## 7. 模块二：宠物档案

### 7.1 新建/编辑表单

新增与编辑共用一页（`pages/pet/edit`），实际为 4 张卡片：

- **头卡**：头像上传 + 名字 + 生日（日期选择器）
- **类型/品种/身份卡**：物种 chips 单选（猫/狗/兔/仓鼠/鸟/爬宠/鱼/其他，禁用 emoji）、品种/种类（自由文本，placeholder 随物种给示例；品种字典当前未接入选择器）、身份 chips（性别或数量，随物种变化）
- **性格卡**：性格标签（预置 10 个：亲人/胆小/活泼/拆家/高冷/吃货/粘人/爱玩/安静/怕生，最多选 5 个 + 自定义输入 ≤8 字）
- **到家/绝育卡**：到家日期、绝育三档（仅猫/狗/兔显示：已绝育/未绝育/不确定）

> 芯片号、证件号、保险、常去医院、过敏源、禁忌食物、目标体重等字段已在云函数白名单预留（见 4.1），**当前版本表单未开放**，无身份组/医疗组折叠区。

**物种差异化字段（`utils/dict.js` SPECIES_FORM）：**
- 鱼：身份字段为「数量」（1 条/2–10 条/10 条以上，当前不落库）、品种标签为「鱼缸/名称」
- 仓鼠/鸟/鱼/爬宠/其他：无「绝育」字段；性别档为 ♀雌性/♂雄性/不确定（存 male/female/unknown）
- 爬宠品种标签为「种类」

**校验规则：**

| 字段 | 规则 | 错误提示 |
|---|---|---|
| 名字 | 必填，1~12 字，去首尾空格 | 「给毛孩子起个名字吧」/「名字最长 12 个字」 |
| 出生日期 | 不得晚于今天 | 「出生日期不能是未来」 |
| 到家日期 | 不得早于出生日期 | 「到家日期应晚于出生日期」 |
| 性格标签 | 最多 5 个 | 「最多选择 5 个性格」 |

**头像上传：**
- 点击头像区 → `wx.chooseMedia`（系统压缩）选图
- 进入自研 `p-cropper` 裁剪浮层：强制 1:1 正方形，movable-view 拖动 + 双指缩放（1~4 倍）
- 输出 ≤800px 正方形 jpg（quality 0.92，体积远低于 500KB，无额外压缩步）后传云存储，路径 `pets/avatar/` 按时间戳命名；已是 cloud:// 的头像不重复上传
- 新增态底部主按钮为「加入档案袋」，编辑态统一为「保存」

**归档入口：** 不在表单内。归档走首页长按卡片弹层（归档有确认弹窗，说明「归档后提醒将暂停，时间线只读，首页不再展示」）；取消归档同样走长按弹层或「我的 → 归档宠物」。**当前版本无删除宠物入口**（云函数 `pet.remove` 保留能力：仅创建者可调，级联停用提醒并删除 records/inventories/diaries，但前端未暴露）。

### 7.2 宠物详情页

**顶部档案头卡：** 圆形头像 + 名字 + 性别符号（♂/♀）+ 副行（品种 · 年龄 · 绝育状态，均空显示「新伙伴」）+ 到家天数 + 右侧目标体重 pill 与「编辑」铅笔按钮（归档时隐藏）。详情页不再单独展示「下次事项」卡片，避免首屏信息拥挤。

**Tab 结构（时间线 / 相册 / 日记本）：**
- **时间线**（默认）：该宠物所有记录按日分组倒序。日期分组头（`8月10日 周日`），每条记录显示类型图标 + 标题 + 摘要 + 值；**备注与照片条在卡片内联展示**（不限于日常类型）。点击整行进记录详情页（编辑/删除在详情页内，时间线无长按手势）。顶部类型筛选条（横向滚动 Chip：全部/健康/喂养/花销/日常；「日常」分组含 daily/便便/呕吐/洗护/遛狗/铲屎/发情/里程碑/自定义）
- **相册**：三列照片网格（按记录日期倒序分页读取 photos），点击图片调起微信原生大图预览（wx.previewImage，支持左右滑动与长按保存）。云文件地址先转换为临时 URL 后再预览
- **日记本**：展示宠物按日期倒序的只读内心日记。每篇包含日期、标题、正文和宠物署名「— 宠物名」。进入 Tab 且内容加载成功后标记当前成员已读（readBy），不提供编辑、删除、不喜欢或重新生成
- 日记为空时展示「今晚还没有收到宝宝的日记」及「明天再来看看，也许会有一篇宝宝自己的小日记」的轻提示；模型失败（status=failed/skipped）不展示半成品
- **分页**：时间线通过 `record.list`、相册通过独立的 `record.photos`、日记通过 `diary.list` 分别使用游标分页；时间线/相册每页 30 条记录，日记每页 20 篇。三者均不一次性拉取全部历史数据，加载失败保留已展示内容并提供重试

**归档态：** 头卡加「已归档」灰签，全页只读——隐藏编辑按钮，时间线空态不显示「+ 记一笔」。恢复入口在首页长按卡片弹层（「取消归档」）和「我的 → 归档宠物」页。归档的完整语义：停用该宠物全部 active 提醒 + 首页默认隐藏 + 全页只读，可随时恢复（字段见 4.1 archived）。**归档态无删除入口。**

## 8. 模块三：记录表单（添加记录页）

### 8.1 通用表单框架

除体重（独立大数字页）外，所有记录类型共用同一页同一骨架（`pages/record/edit`，配置驱动见 `utils/recordMeta.js` FIELD）：顶部宠物选择（picker，可选未归档宠物）→ 类型专属字段区 → 日期（默认今天，可补记过去，不可未来——云端校验 `date` 不得晚于今天）→ 照片（≤9 张）→ 备注 → 底部「保存」主按钮。

**通用逻辑：**
- 保存成功分两档反馈：
  - **低频高价值类型（疫苗/驱虫/就医/手术/用药）**：弹半屏结果卡替代 toast——「✓ 已记下啦」+ 一行下次提醒信息（有 nextDate 显示「下次提醒：X月X日 · 到期前自动推送全家」；未设置则提示「可在提醒页手动添加」）+「完成」按钮。就医/手术附加次级按钮「同步记一笔花销」→ 跳花销表单并预填分类=医疗（金额不预填，无记录关联回写）
  - **其余类型**：轻 Toast「已记下啦」（花销为「已记账」），500ms 后返回来源页
- 连续记录模式：「保存并再记一条」在日频类型（日常/喂食/花销/便便/遛狗/铲屎/饮水/零食）与体重页显示——真实保存后重置表单留在当前页（体重页清空数值输入、保持当前宠物与当天日期，并把「上次记录」刷新为刚保存的这条）；低频类型只保留「保存」
- 从待办/提醒进入的表单支持预填：`v`=疫苗名、`item`=洗护项目、`cat`=花销分类、`reminderId`=保存后联动完成原提醒（疫苗除外，由云端重排）
- **删除联动规则**：删除入口在记录详情页（自绘确认弹层「删除后无法恢复，家庭成员的时间线中也会同步消失」）；云端将该记录派生的 active 提醒一并停用；已发生的库存扣减**不回滚**（喂出去的粮收不回）；编辑疫苗/用药记录时，旧派生提醒删除并按新内容重建；编辑/删除历史驱虫记录时仅清理其早年派生的提醒，不再重建
- 提交幂等：创建携带 `requestId`，重复提交由云端去重返回原记录

### 8.2 各类型表单细节

**体重（独立表单页 `pages/weight`）：**
- 大数字输入卡 + 自定义数字键盘（含小数点；校验层支持「8斤4两」「8.4 斤」等斤两输入自动换算 kg，当前数字键盘未开放「斤」键）
- 加载时回填上次体重并显示「上次记录 · 日期 · N kg」卡
- 保存后即时反馈对比：Toast「已记下啦 · 比上次（↑/↓）0.1kg」
- 合法范围 0.1~100 kg；当前版本无品种参考区间偏离提示

**疫苗：**
- 疫苗 chips 按宠物物种切换字典（`utils/dict.js` VACCINES：猫=猫三联/狂犬/猫白血病/其他，狗=犬四联/犬六联/狂犬/其他；其他物种回退仅「其他」；编辑回填的既有值不在字典内时临时追加进 opts，不静默丢失）+ 针次（第1针/第2针/第3针/加强针）+ 医院、批号（选填）+ 下次日期（选填）
- 从待办进入按 `v` 预填疫苗名（匹配不上选「其他」）
- 保存 → 云端按 nextDate 创建/更新疫苗周期提醒（同宠物同 category 派生提醒去重）

**驱虫：**
- 类型 chips（体外/体内/内外同驱）+ 药品手填；**无周期字段、不派生提醒**，下次驱虫提醒统一在提醒页手工新建（预设事项「驱虫」）
- 从待办进入（提醒页建的驱虫提醒到期）保存后走通用 `reminderId` 链路完成并推进原提醒
- **囤货联动（显式选择）**：若囤货中存在 `consumeMode=byPiece` 且 `linkType=deworm` 的未过期物品，表单显示「从囤货扣减 · 选填」chip 列表（首项「不扣减」，其余为「物品名 · 剩 N 单位」）；**默认不扣**，选中后保存才带 `inventoryId` 由后端校验（归属/未过期/余量>0）并扣 1 件

**就医病历：**
- 医院、症状、诊断、费用（选填，计入账单）四个输入 + 通用照片行；当前版本无「化验单/处方/伤口」照片槽位引导

**用药：**
- 药品、剂量、频次（每日 1/2/3 次）、疗程（开启提醒时必填 1~90 天）、提醒时间多选（08:00/09:00/14:00/21:00，随频次自动带出默认组合）、「生成用药提醒」开关（默认开）
- 保存后云端按每个提醒时间点生成固定日程提醒（`scheduleMode=fixed`、每日、`slotKey=med_i`、起止日期为首尾）
- 服药打卡由提醒完成承载；当前版本无 data.checkins 写入、无漏打标黄

**喂食：**
- 餐次（早餐/午餐/晚餐/加餐）、食物（默认按物种带出主粮名）、克数（选填）、状态（全部吃完/有剩余/没怎么吃）
- **囤货扣减（显式选择）**：存在 `category=粮食` 且按量模式的未过期物品时显示「从囤货扣减 · 选填」chip，选中后保存按克数扣减（见 10.2）；默认不扣
- 当前版本无「喂食计划」，克数无计划值带出

**花销：**
- 金额输入（元，>0）+ 分类图标单选（粮食/零食/医疗/用品/玩具/美容/寄养/保险/其他，9 类）+ 明细（选填）
- 反向联动：就医/手术表单保存后的结果卡提供「同步记一笔花销」一键跳转并预填分类=医疗（见 8.1）；花销表单内无「同时记就医」提示

**便便/呕吐/洗护/遛狗/铲屎/发情/里程碑/自定义：** 均为轻量表单（chips/输入 1~3 个 + 备注 + 照片），字段枚举见 4.2 数据表，遵循通用框架，不赘述。其中遛狗只记「时长」，不记距离（真实用户极少测量，字段即负担）；铲屎无任何结构化字段，仅 日期 + 备注 + 照片。

**记录详情页：** 头卡（类型图标 + 值）+ data.items 逐条展示 + 备注卡 + 相册；照片点击经临时 URL 调起 `wx.previewImage` 预览；提供「编辑这条记录」「删除这条记录」入口（编辑态不显示囤货扣减选择）。

### 8.3 记账页（花销记录的聚合查看页）

- 顶部月份切换（‹ 2026年8月 ›），默认当月，不可切到未来月；其下分类筛选 chip 横条（全部 + 9 类，单选过滤）

- 账单列表：行显示分类图标 + 明细 + 日期 + `-¥金额`；点击跳记录详情页；当前版本**无左滑删除**（删除在记录详情页内）
- 右下角浮动「+」按钮直达记花销表单

## 9. 模块四：提醒中心

### 9.1 提醒管理页

**分区（进行中 / 已完成 两段，p-seg 切换）：**
- 「进行中」：客户端按到期日分三组——**已逾期（红）/ 今天（橙）/ 未来 7 天**，组内按 remindAt 升序；**7 天以后的进行中提醒不在本页展示**。行内容：分类色点 + 「宠物名 · 标题」+ 周期标签（每天/每周/每月/每 N 天/一次性）+ 右侧时间 pill（逾期 X 天/今天/明天/N 天后）。当前版本**无服药合并行、无来源标注**
- 「已完成」：近 30 天 done 记录（只读），按完成时间倒序，行显示「完成于 X 年 X 月 X 日」；**无「查看更早」入口**

**单条操作（无左滑手势）：** 点击行弹底部面板——「同时记一笔」（仅 vaccine/deworm/medication 类显示，跳对应表单；洗护类提醒用标题预选洗护项目）/「确认完成」（周期提醒推进下一周期，一次性标记 done）/「延后 3 天」（副文案显示改期后的真实日期）/「编辑提醒」（跳新建页带 `?id=`）/「停用提醒」（保留历史、不再触发）。**提醒无删除操作。**

**新建提醒（右上角「+ 新建」）——日常护理提醒不走「记一笔」：**
- 表单字段顺序：给哪只（宠物 chips，不含归档宠物）→ 事项（预设模板：梳毛/刷牙/洗澡/剪指甲/洁耳/擦眼睛/铲屎/洗猫砂盆/洗碗/称体重/驱虫/复查 + 自定义，选自定义出现名称输入 ≤12 字）→ 类型（周期提醒 / 一次性提醒；周期提醒显示「每 + N + 天/周/月」，N 手填默认 1，1 天/7 天/30 天映射 daily/weekly/monthly，其余为 custom_days；一次性提醒为 repeatType=none，完成即 done）→ 提醒日期（日期选择器，默认今天；周期提醒下文案为「首次提醒」）→ 提醒时间（默认 21:00）→ 微信提醒范围（全体家庭成员 / 仅提醒我，下方无额外说明文案）
- 提前天数当前固定为 7（表单无「高级」折叠行、无备注字段；编辑保存同样写回 7）
- 事项→分类映射：梳毛/刷牙/洗澡/剪指甲/洁耳/擦眼睛 → groom，铲屎 → litter，洗猫砂盆/洗碗 → custom，称体重 → weight（跳独立体重表单页），驱虫 → deworm（提醒周期由提醒自身配置，到期从待办记一笔后走通用链路完成并推进；记录不再派生/重排提醒），复查 → checkup（跳就医记录）（历史「清理猫砂/洗水碗/滴眼药」提醒 category 不变，不迁移；编辑旧提醒时标题落入自定义项正常展示）
- 「完成后自动记一笔」以完成面板的「同时记一笔」承载（groom 用标题预选洗护项目，custom 类跳自定义记录并预填提醒标题，称体重保存后联动完成原提醒）；**表单内无此开关**
- 到点进入首页待办打卡；未完成的护理提醒在小程序内保持逾期状态，不发送微信补催

### 9.2 提醒生成规则（业务核心）

| 触发事件 | 自动动作 |
|---|---|
| 创建疫苗记录 | 创建/更新疫苗周期提醒（按 nextDate；同宠物同 category 的派生提醒去重） |
| 创建驱虫记录 | **不派生提醒**（驱虫提醒统一在提醒页手工新建，周期/时间由提醒自身配置）；编辑/删除历史驱虫记录时仍会清理其早年派生的提醒 |
| 创建用药记录 | 选择每日 1/2/3 次和具体时刻；开启提醒时疗程必填 1~90 天，按每个时刻生成固定日程（scheduleMode=fixed，slotKey=med_i） |
| 库存余量 ≤ 补货阈值 | 创建补货提醒（立即到期的一次性待办「xx 快没了」）；余量回升后自动停用 |
| 库存临期（填了 expireDate） | 到期前 30、15、3 天及当天 09:00 生成一次性待办并尝试微信提醒；已过去节点不补发（过期当天节点立即提醒）；入库/编辑时先停用旧临期提醒再重建 |
| 生日/到家纪念日前 7 天 | 每年提前 7 天 09:00 生成固定纪念日待办并尝试微信提醒（offsetDays 默认 -7，0=当天）；2 月 29 日在非闰年按 2 月 28 日；日期清空或宠物归档后自动停用 |
| 手动创建 | 支持自定义事项（预设护理模板 + 自定义名称）、周期（每 N 天/周/月）、首次提醒日期与提醒时间、通知范围；提前天数固定 7；remindAt 不允许早于当前时间 1 小时以上 |
| 护理提醒当天未完成 | 在小程序内保持逾期状态，不发送微信补催 |

**去重规则：** 同宠物同 category 的**记录派生**周期提醒（sourceRecordId 非空，当前仅疫苗）只保留一条 active，新记录触发更新而非新增；用户手动创建的同类提醒不被接管。

## 10. 模块五：库存管理（产品内命名「囤货」）

### 10.1 库存列表页

每行显示：分类图标 + 物品名 + 副标题（「还能撑 X 天」（有日均消耗时）/「余 N 单位」/「已用完 · 左滑补货」/「已过期 · 建议处理」）+ 余量进度条（绿 → 橙（≤25% 或低于阈值）→ 红（用完/已过期））。

- 顶部 banner：30 天内最近一条临期物品提示（「N 天后到期」/「已过期 X 天」）+ 临期提醒规则说明（前 1 月 / 15 天 / 3 天 / 当天）
- 点击行 → 物品详情页：余量卡 + 明细（分类/日均消耗/补货阈值/保质期）+ 消耗记录历史（前 20 条，含来源）+「手动消耗」按钮（弹窗输入数量）+「编辑物品」入口。当前版本详情页无 dailyConsume 来源说明文案、无「已用完/已丢弃」处置按钮
- 列表项左滑：**补货**（余量回满购入量）/ **删除**（二次确认，物理删除并停用其派生提醒）；无「消耗一次」手势
- 首页待办出现「猫粮快没了」时，点击直达囤货页并高亮该物品行

### 10.2 核心逻辑

- **入库**：点「+ 入库」进入库表单（入库/编辑共用一页），字段：名称 / 分类（粮食·猫砂·药品·用品）/ 数量 + 单位 / 保质期（date picker，选填）/ 补货阈值（选填）/ 日均消耗（选填，用于「还能撑几天」估算）/ 扣减模式（按量 byAmount·按件 byPiece）/ 关联记录类型（**仅按件时显示**，可选 deworm 驱虫 / medication 用药）/「计入本月账单」开关（默认关，打开后出现金额输入，保存时同步记一笔「用品」分类花销）。保存后 remainAmount += 购入量；入库有 requestId 幂等
- **扣减（记录联动 = 显式选择制，不再自动猜测）**：
  - 记录表单内「从囤货扣减 · 选填」chip 列表（仅 feed/deworm/medication 三类新建时显示，编辑态不显示；候选自动排除已过期物品），首个 chip 为「不扣减」（默认）
  - 按量（byAmount）：喂食记录选中 `category=粮食` 的物品 → 保存时按克数扣减（g/kg 自动换算，单位不可换算则报错）
  - 按件（byPiece）：驱虫/用药记录选中 linkType 匹配的物品 → 保存时扣 1 件
  - 后端校验：物品存在且属本家庭、未过期、余量充足；校验在记录落库前，扣减在落库后（扣减失败不回滚记录，仅服务端日志）
  - 手动：物品详情页「手动消耗」输入数量（不校验过期）
- **临期通知**：expireDate 非空的物品，到期前 30/15/3 天及过期当天 09:00 生成一次性待办并尝试微信提醒（已过去节点不补发，过期当天节点立即提醒）；过期后物品行标红「已过期 · 建议处理」，且从记录表单的扣减候选中排除（后端同样拒绝过期物品扣减）。当前版本**无「已用完/已丢弃」处置状态**，删除物品即物理删除（历史消耗记录随物品删除）
- **补货预警**：扣减/入库后 remainAmount ≤ threshold 或 ≤0 → 立即生成补货待办「xx 快没了」（首页待办可见），物品行副标题与进度条同步变化；余量回升（补货/编辑）后自动停用该提醒
- **dailyConsume 来源**：入库表单手填（当前版本无喂食计划、无近 14 天自动估算）

## 15. 模块十：家庭共享与多人协作（评审新增）

### 15.1 需求背景

实际养宠场景中，同一只宠物常由情侣、夫妻共同照料：一人带去打疫苗，另一人喂药。单人数据孤岛会导致「他不知道已经驱过虫了」的重复操作或遗漏。本模块解决**多人对同一批宠物档案的共同查看与共同记录**。

> 定位边界：这是「协作」不是「社交」。无公开动态、无陌生人、无评论点赞，分享范围严格限定在用户主动邀请的家庭成员内。

### 15.2 核心概念

- **家庭空间**：数据归属的最大单位。一个用户同时只属于一个空间（v1 不做多空间切换，避免复杂度）
- **角色**：创建者（owner，唯一）与成员（member，≤4 人）。**不做细粒度权限矩阵**——所有成员均可查看全部数据、添加/编辑记录，理由是家庭成员间信任成本低于权限管理成本
- **创建者专属权限**：邀请/移除成员、解散空间（均由云端二次校验 owner 身份）

### 15.3 邀请与加入流程

1. 入口：首页顶部家庭成员头像组 / 我的 → 家庭成员 → 邀请
2. 成员点击页面内「邀请家庭成员」按钮（`open-type="share"`）→ 直接调起微信分享面板，生成统一邀请小程序卡片：`imageUrl` 使用邀请插画 `/assets/invite-share.jpg`，标题带家庭名称，路径携带 `familyId`；不引导用户点击右上角分享。发起分享时静默调用 `family.invite` 写入 `family.lastInviteAt` 时间戳——**邀请 7 天过期**（云端在 preview/join 时校验，过期提示「邀请已过期，请让家人重新分享」；前端无倒计时 UI）
3. 被邀请人点开卡片 → 进入落地页（`family.preview`）：显示邀请人、空间名、已有宠物封面（最多 2 张，有头像显示真实头像）、成员头像叠层（最多 3 个，真实头像，无头像爪印兜底）+ 成员数 → 「加入家庭」按钮（下方附「加入即表示同意家庭成员可见你的记录」）
4. 加入校验（云函数 `family.join`，**事务**内重读校验）：成员数 <5 且未在其他空间 → 写入 members（昵称/头像取加入时快照）→ 个人空间数据迁入家庭 → Toast「已加入家庭空间」并回首页
5. 异常态：空间已满 → 落地页整页切换「这个家庭满员啦（最多 5 人）」；已在其他空间、邀请过期、家庭不存在等 → Toast 透传云端提示，无专门页面

**通用分享**：四个 tab 页（宠物/提醒/统计/我的）均支持胶囊菜单「发送给朋友」与「分享到朋友圈」，统一走 `utils/share.js`（标题「毛球档案袋 · 记录毛孩子的每一天」，落地首页，封面 `/assets/share-cover.png`，由 `tools/gen-share-cover.js` 生成的手绘宠物围圈插画）；「我的-关于」组另有「推荐给朋友」行内分享按钮（`open-type="share"`）。子页面不单独配置分享。

### 15.4 成员管理页

- 顶部家庭卡（家庭名 + 共 N 位成员）；成员列表：真实头像（无头像显示稳定配色爪印兜底）+ 显示名（自己优先显示「家庭内称呼」）+ 角色标签（「创建者」chip / 成员无标签）+ 加入时间；底部固定说明「所有成员可查看全部档案并添加记录；移出成员后其历史记录仍会保留并显示昵称」。`family.resolve` 每次查询时自动同步刷新自己的昵称/头像快照，其他成员保持入空间时的快照
- 创建者视角：**点击成员行**弹底部确认面板「移出家庭」（非左滑；前端不校验身份，云端兜底仅创建者可移出）——被移出成员的历史记录保留并仍显示其昵称
- 成员视角：「退出家庭空间」按钮（wx.showModal 二次确认：退出后将无法查看家庭数据）
- 创建者视角另有底部红色「解散家庭空间」（仅成员数 >1 时显示）：强警示 + **输入空间名确认**（输入框占位提示名称、实时比对点亮按钮；云端再校验仅创建者可解散，不重复校验名称）。解散后所有成员失去访问，全部数据归创建者个人空间，其余成员写入 `kickedFrom` 标记

### 15.5 协作体验细节

| 场景 | 逻辑 |
|---|---|
| 记录归属 | 每条记录写入 createdBy + createdByName，记录详情页显示记录人昵称快照 |
| 成员昵称 | members 中为加入时的快照昵称；成员本人可在「我的」资料弹层改「家庭内称呼」（familyNick，仅本空间成员列表中对「自己」生效，不改微信名） |
| 谁完成了提醒 | 提醒完成时云端记录 completedBy + completedByName（当前版本界面仅显示完成时间，不展示完成人） |
| 提醒展示 | 周期提醒和每日用药待办在小程序内展示给家庭成员；微信消息按提醒范围和成员独立授权发送，失败降级为小程序内提醒 |
| 数据冲突 | 当前版本**不做并发冲突检测**（无乐观锁，后写覆盖先写）；实时协同编辑不纳入当前版本 |
| 新成员可见范围 | 加入即可见全部历史数据（家庭信任模型，不设"加入前不可见"） |
| 离线/弱网 | 与个人版一致，提交失败保留表单 |

### 15.6 UI 变更点

- **首页**：大标题左侧显示家庭成员头像组（最多 3 个 + 「+N」），点击进成员管理页
- **记录详情页**：展示记录人昵称快照（createdByName）
- **我的**：「协作与数据」组含「家庭成员」入口（显示成员数）
- **新增页面**：家庭成员管理页（成员列表 + 邀请按钮 + 移出/退出/解散）、邀请落地页

### 15.7 审核合规

- 功能描述使用「家庭成员共享」，避免「社区/圈子/群」字眼
- 分享卡片文案不出现诱导分享词（「转发」「邀请有礼」等），保持纯功能性邀请

### 15.8 被移出 / 家庭解散后的处理

- 被移出成员或家庭已解散的成员打开小程序 → **首页全屏拦截层**「你已不在该家庭」+ 副文案「家庭数据不再可见；你加入前的个人数据仍保留」+「回到我的个人空间」按钮（点击清空 `kickedFrom` 标记并回到个人空间；当前拦截层仅覆盖首页 Tab）
- 标记机制：云端 `family.removeMember` / `family.dissolve` 向目标成员 settings 写入 `kickedFrom`（家庭名）；该字段不在客户端写白名单（仅服务端可写，客户端仅可清空，见 4.5）
- 数据归属（v1 简化）：加入家庭时个人空间数据迁入家庭空间；退出 / 被移出后**数据留在原家庭空间、不回迁**，仅失去访问；家庭解散时全部数据归创建者个人空间，其余成员仅失去访问

## 16. 非功能需求

| 项 | 要求 |
|---|---|
| 首屏启动 | 冷启动到首页可交互 ≤ 2s（首页数据合并为 1 次云函数调用） |
| 图片 | 头像经自研裁剪输出 ≤800px jpg；记录照片走 `chooseMedia` 系统压缩；列表页用缩略图（image 组件 mode + 懒加载） |
| 兼容性 | 基础库 ≥ 2.32.0；iOS/Android 微信最新两个大版本 |
| 数据量假设 | 单用户 10 宠 × 每宠 1000 条记录内，列表/图表流畅 |
| 隐私 | 不出隐私协议之外的任何数据；类目「工具 > 效率」；无 UGC，无需内容安全审核接口（用户自己看自己的数据） |
| 合规底线 | 安全食物查询页底部带固定文案「仅供参考，不能替代兽医诊疗」；喂食量计算结果卡注明估算口径仅供参考（症状自查功能不存在） |

## 19. 风险与开放问题

| 风险 | 应对 |
|---|---|
| 家庭共享导致数据权限复杂度上升 | 读写全部走云函数中转 + members 校验（4.7），客户端零直连；上线前针对越权读写写安全测试用例 |
| 个人主体类目审核 | 文案全链路规避「社区/动态/分享」字眼；分享图仅保存相册不留小程序内传播 |
| 云开发免费额度 | 图片走压缩 + 云存储生命周期策略；超额后引导用户开通按量付费（成本极低） |
| 多宠物联动逻辑复杂度 | 提醒去重、库存联动等规则已在第 9/10 章显式定义，开发前先写单测用例 |
| 第三方模型不可用或输出不稳定 | 服务端开关与超时降级；输出严格 JSON/长度/禁用词校验；失败不展示半成品且不影响主流程 |
| AI 日记产生隐私或情绪操纵风险 | 只发送最小化摘要，不发送成员身份和图片；提示词禁止诊断、威胁、愧疚和控制性表达 |
