## 1. 产品概述

### 1.1 产品定位

一款面向养宠人士的**宠物信息记录与管理工具**。帮助用户系统化管理宠物档案、健康医疗、喂养生活、花销账目，并通过智能提醒避免遗忘疫苗、驱虫等关键事项。

### 1.2 一句话 slogan

「每只毛孩子，都值得一份完整的档案。」

### 1.3 目标用户

- **主要人群**：25~40 岁城市养宠青年，养 1~3 只猫/狗
- **次要人群**：多宠家庭、宠物繁育人、救助站志愿者（多宠管理刚需）
- **用户痛点**：
  1. 疫苗/驱虫时间靠脑子记，经常忘
  2. 病历、化验单散落各处，就诊时说不清病史
  3. 养宠花销没概念，月底一算吓一跳
  4. 换手机后记录全丢

### 1.4 设计原则

1. **工具优先**：所有功能围绕「记录—提醒—查询」闭环，不做 Feed、不做社区
2. **三步可达**：任何记录操作从首页出发不超过 3 步
3. **多宠平等**：所有功能默认支持多宠物，数据结构从第一天就按多宠设计
4. **数据属于用户**：支持完整导出，绝不绑架数据
5. **克制打扰**：提醒宁缺毋滥，用户可完全掌控

### 1.5 竞品参考（差异化）

- 宠日常 / 小佩宠物：绑硬件或社区，臃肿 → 我们纯工具、轻量
- 通用备忘录/Excel：不懂宠物业务 → 我们有疫苗周期、品种体重区间等宠物领域知识内置

## 2. 名词定义

| 名词 | 定义 |
|---|---|
| 宠物档案 | 一只宠物的基础信息实体，系统的核心数据单元 |
| 记录 | 挂在某只宠物名下的任一条数据（体重/疫苗/花销等统称） |
| 时间线 | 某只宠物所有记录按时间倒序的聚合视图 |
| 提醒 | 由系统或用户创建的待办事项，分周期型和一次性 |
| 待办 | 已到期或临近到期（7天内）的提醒 |
| 囤货（库存） | 猫粮、猫砂、驱虫药等家里囤的消耗品管理单元：余量 + 保质期 + 记录联动扣减 |
| 快捷记录 | 首页弹出的九宫格快速录入面板 |

### 3.2 底部 Tab 结构（4 个 Tab）

| Tab | 页面 | 说明 |
|---|---|---|
| 宠物 | 首页（卡片墙） | 核心入口 |

### 4.1 `pets` 宠物集合

| color | string | 否 | 毛色 |
| neutered | bool | 是 | 是否绝育 |
| chipNo | string | 否 | 芯片号 |
| certNo | string | 否 | 犬证/免疫证编号 |
| insurance | object | 否 | {company, policyNo, expireAt} |

| 字段 | 类型 | 说明 |
|---|---|---|
| _openid | string | 云开发自动写入（创建者），仅用于审计与「我创建的」筛选，数据可见性以 familyId 为准 |

| petId | string | 关联宠物（通用物品可空） |
| itemName | string | 物品名 |
| category | string | food/litter/medicine/supply |
| totalAmount | number | 购入量 |
| remainAmount | number | 当前余量 |
| unit | string | kg/袋/粒/片/支/包 |

### 4.5 `settings` 用户设置集合（每用户一条）

| 字段 | 说明 |
|---|---|
| theme | light/dark/auto |
| defaultCycles | {dewormInternal: 90, dewormExternal: 30, vaccine: 365, bath: 30} |
| budget | 月度预算（分） |
| homeLayout | 首页布局偏好 |
| backupAt | 上次备份时间 |

### 4.6 `families` 家庭空间集合（多人协作）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| _id | string | 是 | 家庭空间 ID |
| name | string | 是 | 空间名（默认「XX 的档案袋」，可改，≤12 字） |
| ownerOpenid | string | 是 | 创建者 |
| members | array | 是 | 成员列表：[{openid, nickname, avatar, role, joinedAt}]，role: owner/member，上限 5 人 |
| createAt | number | 是 | 时间戳 |

**派生规则：**
- 每个用户首次进入自动创建一个个人空间（默认成员仅自己），邀请首位成员后升级为家庭空间
- `pets / records / reminders / inventories` 四个集合均通过 `familyId` 归属空间；同一空间内所有成员可读、可新建记录
- `createdByName` 为昵称快照，避免成员改名后历史记录显示异常

### 4.7 索引与安全规则

- **共享带来的权限变更**：默认「仅创建者可读写」规则不再适用。所有数据读写改走**云函数中转**（云函数内校验：请求人 openid 是否存在于目标 familyId 的 members 中，不在则拒绝），客户端不直连数据库
- 所有集合保留 `_openid` 字段用于审计与「我创建的数据」筛选
- `records` 建联合索引：`petId + date desc`
- `reminders` 建索引：`status + remindAt asc`

## 5. 全局通用交互规范

### 5.1 导航规范

- 首页卡片点击进入宠物详情页，详情页内所有 Tab 数据**锁定当前宠物**，页面间不丢失宠物上下文
- 返回逻辑：详情页返回首页；二级表单页返回来源页并触发数据刷新
- 所有页面左上角返回按钮保持微信原生，不自定义

### 5.2 空状态规范

| 场景 | 展示 |
|---|---|
| 首页无宠物 | 居中插画 + 「添加第一只毛孩子」主按钮 |
| 时间线无记录 | 插画 + 「还没有记录，点右下角 + 记一笔」 |
| 无待办提醒 | 显示「今天一切安好」并 3 秒后自动收起 |
| 图表无数据 | 「记录 3 次以上体重，就能看到趋势啦」 |

### 5.3 加载与错误

- 首屏加载：骨架屏（卡片轮廓），不转圈
- 列表加载：上拉加载更多，每页 20 条
- 提交失败：Toast「网络开小差了，请重试」，表单数据**保留不清空**
- 云函数超时：8 秒超时，自动重试 1 次后报错
- 图片上传失败：单张失败不影响其他张，失败张显示重传角标

### 5.4 权限与隐私

- 头像上传、相册选择：调起微信原生选择器，不申请相册读写权限
- 订阅消息：在**用户创建第一条提醒时**发起授权申请，附带说明文案「授权后，疫苗驱虫到期会微信通知你」
- 用户拒绝授权：不打断流程，降级为「小程序内红点 + 待办列表」，并在提醒页顶部常驻「开启微信通知」引导条

### 5.5 订阅消息推送逻辑

```
定时云函数（每小时执行）：
1. 查询 status=active AND remindAt <= now+24h AND subscribeAuth=true 的提醒
2. 调微信 subscribeMessage.send 推送
3. 推送成功 → 若是周期提醒：remindAt += 周期；若一次性：status=done
4. 推送失败（用户未授权余量）→ 标记 pushFailed=true，仅小程序内展示
```

> 微信订阅消息为「一次授权一次推送」机制，因此每次推送成功后，下次进入小程序时在提醒页静默引导补充授权（wx.requestSubscribeMessage 需用户手势触发，放在「完成提醒」按钮点击后顺带发起）。

### 5.6 危险操作分级防护

| 操作 | 防护级别 |
|---|---|
| 删除记录 | 普通确认弹层（按类型附联动后果说明，见 8.1） |
| 删除宠物 / 解散家庭空间 | 输入名称确认（输入框预填占位提示名称、实时比对，匹配才点亮按钮） |
| 恢复备份 | 恢复前自动先做一次当前数据备份（「恢复前自动备份」），再给覆盖确认 |

## 6. 模块一：首页（宠物卡片墙）

### 6.1 页面结构（自上而下）

1. **顶部栏**：「我的毛孩子们」大标题（标题左侧并入家庭成员头像组，最多 3 个 + 「+N」，点击进成员管理页）+ 右侧「+ 添加」按钮 + 铃铛图标（仅作红点镜像：有待办时显示红点，点击直接落提醒 Tab，不单独 push 页面）
2. **全局待办区**（条件渲染）
3. **统计速览横幅**（横向滑动，3 张卡片）
4. **宠物卡片网格**（双列）
5. **右下角浮动「+」快捷记录按钮**

### 6.2 宠物卡片

**展示内容（按优先级）：**
- 头像（圆角矩形，占卡片顶部 60% 高度，无头像显示物种默认剪影）
- 名字 + 性别图标（♂蓝 / ♀粉）
- 年龄（`3岁2个月`，无出生日期显示「年龄未知」）
- 最新体重（`4.2 kg`，7 天内更新过显示「· 新」角标）
- 最近临期提醒一行（`疫苗 12天后`，前缀为疫苗类型的矢量线性图标；逾期显示红色 `已逾期 2 天`）

**交互逻辑：**

| 手势 | 行为 |
|---|---|
| 点击卡片 | 跳转宠物详情页（默认落在「时间线」Tab） |
| 点击卡片右上角「+」 | 弹出快捷记录面板，**已预选该宠物** |
| 长按卡片 | 进入编辑模式：卡片抖动，显示「排序拖动」「编辑」「归档」操作 |
| 编辑模式下拖动 | 松手后按新顺序更新所有宠物 order 字段（批量云函数一次提交） |

**边界处理：**
- 仅 1 只宠物：单列大卡布局，头像更大，额外展示「到家 X 天」
- 超过 6 只：网格高度自适应滚动，不分页
- 归档宠物：不展示在首页，在「我的 → 归档宠物」中查看（数据保留，时间线只读）

### 6.3 全局待办区

**数据来源：** 聚合当前用户所有宠物的 `status=active AND remindAt - advanceDays <= now` 的提醒，按 `remindAt` 升序。

**展示规则：**
- 排序：逾期 > 今天 > 未来 7 天，各组内按到期时间升序；逾期超过 3 天的额外加重显示「已逾期 N 天」
- 最多显示 3 条，超过显示「共 X 条待办 >」跳提醒管理页
- 每条显示：宠物头像缩略 + 标题 + 时间状态（`明天到期` / `已逾期 2 天`，逾期红色）
- 行内不放操作按钮，整行即热区

**主操作（统一为底部弹层）：**
1. 点击待办行 → 底部弹层三选项一屏说清：「同时记一笔」（如疫苗提醒 → 快捷创建疫苗记录表单并预填）/「仅完成」/「延后 3 天」
2. 用户选「仅完成」→ 周期提醒推进到下一周期，一次性提醒标记 done
3. 用户选「同时记一笔」→ 跳对应表单页，提交成功后联动完成提醒
4. 右滑单条为等价快捷手势（完成 / 延后），与弹层结果一致

**「延后」逻辑：** remindAt += 3 天，不改变周期（只影响本次）。

### 6.4 统计速览横幅

横向滑动 3 张卡：
1. **本月花销**：`¥326.50`，超预算时数字变橙 + 「已超预算 12%」
2. **本周打卡**：喂食/遛狗打卡次数，附连续打卡天数
3. **体重变化**：所有宠物最近一次体重 vs 上一次（↑红 ↓绿，±0.1kg 内视为持平）

点击每张卡跳对应模块页；「本周打卡」无独立模块页，点击跳统计页并锚定到打卡热力卡。

### 6.5 快捷记录面板（九宫格）

**唤起方式：** 首页浮动「+」按钮 / 卡片「+」按钮。

**面板内容（九宫格两页，共 18 种记录类型）：**
- 第一页（高频）：体重｜喂食｜日常｜疫苗｜驱虫｜就医｜用药｜花销｜更多（用药提频：疗程内为日频；便便挪至第二页）
- 第二页（低频）：洗护｜呕吐｜便便｜手术｜遛狗｜饮水｜零食｜发情｜里程碑｜自定义
- 翻页：点「更多」或底部圆点横向滑动切换，分页指示器联动；美容归入洗护（groom 子项含洗澡/剪指甲/美容等）
- 「日常」类型：面向"随手拍"场景，表单仅 文字（选填）+ 照片（1-9 张，至少一项非空），无任何结构化字段，3 秒可完成一笔；在时间线中以完整图文卡片展示（全文 + 照片九宫格，不折叠），点击进入详情可编辑/删除

**交互逻辑：**
- 从卡片「+」唤起：宠物已锁定，点类型直接进表单
- 从浮动「+」唤起：点类型后若用户有多只宠物，先弹宠物选择半屏弹层（默认选中最近记录过的宠物），再进表单；宠物 ≤1 只时面板不渲染宠物选择行，直接进表单
- 面板背景为毛玻璃半屏弹层，点击空白处收起，有下拉关闭手势

### 6.6 首次添加宠物后的新手引导

添加第一只宠物成功后，成功页改为三选引导卡（每步可跳过、可日后补，不阻塞）：

1. 「补全生日」→ 跳档案编辑页并聚焦生日行（有生日才有年龄、纪念日提醒）
2. 「记第一条体重」→ 直达体重表单
3. 「开启微信提醒」→ 说明文案 + 订阅消息授权

全部跳过则回首页，引导条缩为卡片墙顶部一条可关闭的轻提示，填完一项消一项。

**引导通用原则：** 所有引导（授权、补全档案等）遵循「出现 → 可关闭 → 降级为设置行 → 限时复现 ≤3 次」，绝不硬阻断。

## 7. 模块二：宠物档案

### 7.1 新建/编辑表单

**分组展示：**
- 必填组：头像、名字、物种（图标单选：猫/狗/兔/仓鼠/鸟/爬宠/鱼/其他，使用矢量线性剪影图标，禁用 emoji）、性别
- 基础组：品种（物种=猫/狗时弹出品种选择器，支持搜索；其他物种手填）、出生日期、到家日期、毛色、是否绝育
- 身份组（折叠）：芯片号、证件号、保险信息
- 医疗组（折叠）：常去医院、医生电话（点击直接调起 wx.makePhoneCall）、过敏源、禁忌食物
- 性格组（折叠）：性格标签（预置：亲人/胆小/活泼/拆家/高冷/吃货，最多选 5 个 + 自定义）、目标体重

**物种差异化字段（原型已落地）：**
- 鱼：以「数量」替代性别、「鱼缸名」替代品种
- 仓鼠/鸟/爬宠：无「是否绝育」字段；性别除 male/female 外带「不确定」档

**校验规则：**

| 字段 | 规则 | 错误提示 |
|---|---|---|
| 名字 | 必填，1~12 字，去首尾空格 | 「给毛孩子起个名字吧」 |
| 物种 | 必选 | 「请选择物种」 |
| 出生日期 | 不得晚于今天 | 「出生日期不能是未来哦」 |
| 到家日期 | 不得早于出生日期 | 「到家日期应该晚于出生日期」 |
| 目标体重 | 0.1~100 kg | 「体重数值不太对」 |

**头像上传：**
- 点击头像区 → 底部弹层「拍照 / 从相册选择」
- 选择后进入裁剪页（强制 1:1 圆形预览框，可缩放拖动）
- 压缩至 ≤500KB 后传云存储，路径 `avatars/{openid}/{petId}.jpg`
- 上传中显示进度环，失败可重试

**归档 / 删除入口（仅编辑态）：**
- 编辑态底部两行：归档（中性字）/ 删除宠物（红色 Destructive）；新增态不显示这两行
- 删除宠物二次确认弹窗：「删除后，豆豆的所有记录、照片、提醒将一并删除，且无法恢复」+ 输入宠物名字确认（防误触；输入框预填占位提示名字、实时比对，匹配即点亮删除按钮）
- 删除执行：云函数级联删除 records/reminders/inventories + 云存储图片

### 7.2 宠物详情页

**顶部档案头卡：** 大头像 + 名字 + 品种 + 年龄 + 到家天数 + 性别/绝育图标 + 右上角「编辑」按钮。下拉头卡有回弹视差效果。

**Tab 结构：**
- **时间线**（默认）：该宠物所有记录按日分组倒序。日期分组头（`8月10日 周日`），每条记录显示类型图标 + 摘要 + 照片缩略（最多 3 张）。点击展开详情卡片；长按弹出「编辑/删除」。顶部类型筛选条（横向滚动 Chip：全部/健康/喂养/花销/日常）
  - 例外：「日常」类型不做压缩行，直接内联展示完整卡片——全文文字 + 照片九宫格（>9 张时详情内查看全部），上下与其他记录保持同样间距；筛选 Chip「日常」分组包含 daily/便便/洗护/遛狗/里程碑
- **健康**：疫苗/驱虫/病历/用药/手术 五个子区块，各显示最近一条 + 「查看全部」；体重曲线缩略图（近 90 天），点击进体重详情页
- **花销**：本月金额 + 分类饼图缩略 + 最近 5 条账单，点击进记账页（已按该宠物过滤）
- **相册**：三列照片网格（取所有记录里的 photos），点击大图预览（支持左右滑、保存到相册）

**归档态：** 头卡加「已归档」灰签，Tab 全部只读，FAB 与编辑入口隐藏，仅保留「恢复 / 删除」入口。归档的完整语义：停用该宠物全部 active 提醒 + 不参与库存联动匹配 + 时间线只读 + 首页隐藏，可随时「恢复」回原状（字段见 4.1 archived）。

## 8. 模块三：记录表单（添加记录页）

### 8.1 通用表单框架

所有记录类型共用同一骨架：顶部宠物选择（锁定则只读）→ 类型专属字段区 → 日期时间（默认此刻，可选过去，不可未来）→ 照片（≤9 张）→ 备注 → 底部「保存」主按钮。

**通用逻辑：**
- 保存成功分两档反馈：
  - **低频高价值类型（疫苗/驱虫/就医/手术/用药）**：弹半屏结果卡替代 toast——「✓已记下」+「下次提醒：2026-11-11」+「修改周期」按钮 +「完成」；就医类（就医/手术）附加次级按钮「同步记一笔花销 ¥380」→ 跳花销表单预填金额与分类=医疗，保存后两笔记录互相关联（note 自动带「关联就医记录」）。3 秒无操作自动收起，回来源页并刷新
  - **日频类型**：维持轻 Toast「已记下啦」，不打扰
- 表单未保存时点返回：若有改动，弹「放弃这次记录吗？」
- 连续记录模式：「保存并再记一条」仅在日频类型（喂食/体重/花销/便便/饮水/零食/遛狗/日常）显示；低频类型只保留「保存」
- **删除联动规则**：删除带派生提醒（sourceRecordId 非空）的记录时，确认弹层提示「下次提醒将重新按周期计算」；已发生的库存扣减**不回滚**（喂出去的粮收不回）；删除医疗类记录时提示「关联的花销记录保留」

### 8.2 各类型表单细节

**体重：**
- 大数字输入框（kg，保留 1 位小数）+ 快捷换算（支持输入斤自动换算）
- 保存后即时反馈对比：「比上次（8月3日 4.1kg）↑ 0.1kg」
- 偏离品种参考区间 ±20% 时黄色提示「体重变化较大，留意观察」

**疫苗：**
- 疫苗名：预置字典（猫：猫三联/狂犬；狗：犬四联/犬六联/狂犬）+ 自定义
- 下次日期：默认按设置里的疫苗周期（365 天）自动算出，可改
- 保存 → 自动创建/更新疫苗周期提醒

**驱虫：**
- 内驱/外驱 Tab 切换；产品名手填（带历史输入联想）
- **囤货联动**：若囤货中存在 linkType=deworm 的药品，药品行直接显示「大宠爱（体外）· 剩 2 支」，保存后自动消耗 1 支；库存为 0 或已过期时该行标红「库存不足，点我补货」，不阻塞记录。补货闭环：点击红色药品行 → 入库表单（预填物品名/分类/linkType）→ 保存入库后返回驱虫表单，表单数据保留不清空，药品行刷新为新余量
- 下次日期默认：内驱 90 天 / 外驱 30 天（可在设置改）
- 提醒开关命名为「下次到期提醒」，副文案「做完一次，自动安排下次」——即每次保存驱虫记录后，系统按周期滚动生成下一次提醒（避免「续期」等黑话）

**就医病历：**
- 症状（多选常见词 + 手填）、诊断、处方、医院、医生、花费
- 照片位命名引导：「化验单」「处方」「伤口」三个上传槽位（实际统一存 photos，仅做 UI 引导）

**用药：**
- 药品名、单次剂量、每日次数（1~4 次）、起止日期
- 保存后生成服药计划：起止期间每天生成打卡项，出现在首页待办「今天该喂药了（第 2/3 次）」
- 每次打卡写入 data.checkins，漏打 2 天以上在详情页健康 Tab 标黄

**喂食：**
- 餐次（早/中/晚/加餐，按当前时间默认选中）、品牌（历史联想）、克数
- 若设置了喂食计划，克数默认带出计划值
- 保存后联动扣减对应库存（见库存模块）

**花销：**
- 金额输入（大键盘，最大 ¥999,999）+ 分类图标单选（粮食/零食/医疗/用品/玩具/美容/寄养/保险/其他，9 类）+ 物品名（选填）
- 选择「医疗」时提示「要不要同时记一条就医记录？」一键跳转并预填花费；反向同理：就医/手术表单填了费用后，保存结果卡提供「同步记一笔花销」一键跳转（见 8.1）

**便便/呕吐/洗护/遛狗/发情/里程碑：** 均为轻量表单（核心字段 1~3 个 + 备注 + 照片），遵循通用框架，不赘述。其中遛狗只记「时长」，不记距离（真实用户极少测量，字段即负担）。

### 8.3 记账页（花销记录的聚合查看页）

- 顶部月份切换（‹ 2026年8月 ›），默认当月；其下分类筛选 chip 横条（9 类，可多选过滤）
- 预算卡：月度预算进度条，超预算时进度条变 Pop 色 + 一行说明「超出 ¥72，医疗占比最高」；预算设置入口直接放在该卡右上角齿轮
- 账单列表：点击进账单详情；左滑快捷删除（与时间线手势一致）

## 9. 模块四：提醒中心

### 9.1 提醒管理页

**分区：**
- 「进行中」：所有 active 提醒按到期时间升序，显示宠物头像 + 标题 + 到期日 + 周期标签；每条标注来源（记录自动生成 / 手动创建）。服药类当日多次合并为一行「速诺 50mg · 今日第 2/3 次」，全部完成后该行变灰打勾，次日重置
- 「已完成」：近 30 天 done 记录（只读）；区底部「查看更早」→ 按月份折叠的只读列表

**单条操作：**
- 「进行中」区左滑：完成 / 延后 3 天 / 停用（停用 = 保留历史、不再触发，可在编辑里重新启用）
- 「已完成」区左滑：彻底删除（删除仅对已完成区开放）
- 点击：进入编辑（改时间、周期、提前天数）

**新建提醒（右上角「+ 新建」）——日常护理提醒不走「记一笔」：**
- 表单：给哪只（单宠跳过）→ 事项（预设护理模板：梳毛 / 刷牙 / 剪指甲 / 清理猫砂 / 洗水碗 / 滴眼药 + 自定义）→ 周期（统一为「每 N 天 / 每 N 周 / 每 N 月」，N 手填 1~99，默认每 1 天；不设快捷项，"每天"即每 1 天，避免两套周期并存的选择负担）→ 提醒时间（默认 21:00）→ 通知范围（全体家庭成员 / 仅自己）
- 表单底部折叠行「高级」：提前天数（默认 7）、备注
- 「完成后自动记一笔」开关（默认开）：打卡时按事项映射写入对应轻量记录——梳毛/剪指甲 → 洗护（子项），刷牙/滴眼药 → 洗护（子项），清理猫砂/洗水碗 → 不写入（无对应类型）；关闭则只打卡不留痕
- 到点进入首页待办打卡；当天 22:00 仍未完成则补催一次：通知范围=全体 → 发给所有已授权成员；范围=仅自己 → 只催创建者；每条提醒每天最多补催 1 次，不轰炸

**订阅授权引导条：** 页面顶部常驻「开启微信通知」引导条，文案场景化（「上次疫苗提醒差点错过？开启微信通知，到期直接服务通知你」）；可关闭，关闭后降级为提醒页设置行，7 天后复现一次，最多复现 3 次后不再主动出现（遵循 6.6 引导通用原则）。

### 9.2 提醒生成规则（业务核心）

| 触发事件 | 自动动作 |
|---|---|
| 创建疫苗记录 | 创建/更新疫苗周期提醒（nextDate） |
| 创建驱虫记录 | 同上（内驱/外驱各一条） |
| 创建用药记录 | 生成每日服药待办（起止期间） |
| 设置喂食计划 | 生成每日喂食提醒（可选开启） |
| 库存低于阈值 | 创建补货提醒（触发一次） |
| 库存临期（填了 expireDate） | 到期前 1 个月、15 天、3 天、过期当天，各推送一次全体家庭成员 |
| 生日/到家纪念日前 7 天 | 生成纪念日待办（每年重复） |
| 手动创建 | 支持完全自定义（标题/时间/周期/提前天数）；护理类用预设模板（梳毛/刷牙/剪指甲等），支持「每 N 天」 |
| 护理提醒当天 22:00 未完成 | 补催一次：通知范围=全体则催所有已授权成员，仅自己则只催创建者；每条每天最多 1 次，不轰炸 |

**去重规则：** 同宠物同 category 的周期提醒只保留一条 active，新记录触发更新而非新增。

## 10. 模块五：库存管理（产品内命名「囤货」）

### 10.1 库存列表页

每行显示：物品名 + 分类图标 + 余量进度条（绿→黄→红）+ 「预计还能撑 X 天」（remainAmount / dailyConsume）。

- 点击行 → 物品详情小页：消耗记录历史 + 手动消耗按钮 + 编辑入口 + dailyConsume 来源说明（如「按近 14 天喂食记录估算，日均 45g」，估算天数对不上时可排查）
- 首页待办出现「猫粮快没了」时，点击直达囤货页并高亮该物品行（闪烁一次）

### 10.2 核心逻辑

- **入库**：点「+ 入库」进入库表单，完整字段：名称 / 分类（粮食·猫砂·药品·用品）/ 数量+单位 / 保质期（药品、食品行内强提示「建议填写，临期会提醒」）/ 补货阈值 / 扣减模式（按量·按件）/ 按件时选择关联记录类型 / 「同时记一笔花销」开关。保存后 remainAmount += 购入量，回列表顶部插入
- **扣减**：
  - 按量（consumeMode=byAmount）：喂食记录保存时，若匹配到 category=food 的库存项（按 petId 匹配），remainAmount -= 克数
  - 按件（consumeMode=byPiece）：保存 linkType 对应记录时 remainAmount -= 1。典型链路：记驱虫选药品「大宠爱（剩 2 支）」→ 保存后自动扣 1 支；用药同理
  - 手动：列表项左滑「消耗一次」（输入消耗量）
- **临期通知**：expireDate 非空的物品，在到期前 1 个月、15 天、3 天、过期当天各推送一次全体家庭成员（订阅消息 + 首页待办）；过期后物品行标红「已过期」，不再参与联动扣减（记录表单里该药品显示「已过期，先补货」）；过期行提供处置出口「已用完 / 已丢弃」→ 归档该物品（列表不再显示，历史消耗记录保留）
- **补货预警**：remainAmount ≤ threshold 或「还能撑 ≤7 天」→ 物品行显示「该买了」+ 首页待办出现「猫粮快没了」；按件物品扣到 0 时，对应记录表单的药品行变为「库存不足，点我补货」
- **dailyConsume 来源**：喂食计划自动计算 > 近 14 天喂食记录均值 > 手填

## 13. 模块八：工具箱

入口：「我的」页「工具箱」分组（年龄换算 / 喂食量计算 / 安全食物查询 / 附近医院四行）。纯前端计算/查询，不写库，无需登录态数据：

| 工具 | 逻辑 |
|---|---|
| 年龄换算 | 猫：`人龄 = 15 + 9*(n-1)`（n≤2 特殊段）；狗按体型三档系数表；输入出生日期直接出结果。支持「用档案里的毛孩子」一键选择，自动带出出生日期 |
| 喂食量计算 | 按公式 `每日热量 = 体重^0.75 * 系数（年龄/绝育/活动量）`，再按所喂粮热量（kcal/g，可手填）换算克数。支持「用档案里的毛孩子」一键带出体重/绝育状态，也可手输 |
| 安全食物查询 | 内置 100+ 条禁忌食物数据（离线 JSON），支持搜索，按「剧毒/有害/少量可/安全」四档色标；结果卡底部固定免责文案「仅供参考，不能替代兽医诊疗」；剧毒档顶部加 Danger 色横幅「立即联系宠物医院」，档案 vetInfo 有值时可一键拨打 |
| 附近医院 | 调腾讯地图选点 + 关键词「宠物医院」检索，列表展示距离/电话，点击跳微信内置地图导航；地图 key 失效时降级为「打开微信地图搜索宠物医院」跳转 |

## 15. 模块十：家庭共享与多人协作（评审新增）

### 15.1 需求背景

实际养宠场景中，同一只宠物常由情侣、夫妻共同照料：一人带去打疫苗，另一人喂药。单人数据孤岛会导致「他不知道已经驱过虫了」的重复操作或遗漏。本模块解决**多人对同一批宠物档案的共同查看与共同记录**。

> 定位边界：这是「协作」不是「社交」。无公开动态、无陌生人、无评论点赞，分享范围严格限定在用户主动邀请的家庭成员内。

### 15.2 核心概念

- **家庭空间**：数据归属的最大单位。一个用户同时只属于一个空间（v1 不做多空间切换，避免复杂度）
- **角色**：创建者（owner，唯一）与成员（member，≤4 人）。**不做细粒度权限矩阵**——所有成员均可查看全部数据、添加/编辑记录，理由是家庭成员间信任成本低于权限管理成本
- **创建者专属权限**：修改空间名、邀请/移除成员、删除宠物、解散空间

### 15.3 邀请与加入流程

1. 入口：首页顶部家庭成员头像组「+」/ 我的 → 家庭成员 → 邀请
2. 创建者点击「邀请家庭成员」→ 调起微信原生分享（`wx.shareAppMessage`），生成小程序卡片：标题「邀请你一起记录豆豆的档案」，路径携带 `familyId`
3. 被邀请人点开卡片 → 进入落地页：显示空间名、已有宠物封面、成员头像 → 「加入家庭」按钮
4. 加入校验（云函数）：成员数 <5 且未在其他空间 → 写入 members → 提示「已加入，和 XX 一起记录吧」
5. 异常态：已在其他空间 → 提示「你已在另一个家庭中，需先退出」（退出入口直达）；空间已满 → 「这个家庭满员啦（最多 5 人）」

### 15.4 成员管理页

- 成员列表：头像 + 昵称 + 角色标签（「创建者」金色 chip / 成员无标签）+ 加入时间
- 创建者视角：成员行左滑「移出家庭」（二次确认：其历史记录保留并仍显示其昵称）
- 成员视角：「退出家庭」（二次确认：退出后不再可见该空间数据，历史记录保留）
- 创建者退出 = 解散空间（强警示 + **输入空间名确认**，与删除宠物同级防护，见 5.6：解散后所有成员失去访问，数据仅创建者保留为个人空间）。「移出成员 / 退出家庭 / 解散空间」三个危险操作均走二次确认弹层，文案按上文口径

### 15.5 协作体验细节

| 场景 | 逻辑 |
|---|---|
| 记录归属 | 每条记录写入 createdBy + createdByName，时间线、账单、打卡均显示「谁记的」（小字昵称） |
| 成员昵称 | 默认取微信昵称；成员本人可在成员页改「家庭内称呼」（仅本空间显示，不改微信名） |
| 谁完成了提醒 | 提醒完成时记录 completedByName，待办列表显示「爸爸已完成」 |
| 提醒推送 | 周期提醒推送给**创建该提醒的人**；每日服药/喂食待办推送给**所有开启订阅的成员**（避免一人漏喂） |
| 数据冲突 | 云函数写入前校验记录 updateAt，若他人已更新则返回最新版本并提示「这条记录刚被 XX 修改过」（乐观锁，v1 不做实时协同编辑） |
| 新成员可见范围 | 加入即可见全部历史数据（家庭信任模型，不设"加入前不可见"） |
| 离线/弱网 | 与个人版一致，提交失败保留表单 |

### 15.6 UI 变更点

- **首页**：大标题旁显示家庭成员头像组（最多 3 个 + 「+N」），点击进成员管理页
- **时间线/账单**：每条记录副标题末尾加「· 爸爸 记」
- **我的**：新增「家庭成员」入口（位于数据管理组上方）
- **新增页面**：家庭成员管理页（成员列表 + 邀请按钮 + 角色管理）

### 15.7 审核合规

- 功能描述使用「家庭成员共享」，避免「社区/圈子/群」字眼
- 分享卡片文案不出现诱导分享词（「转发」「邀请有礼」等），保持纯功能性邀请

### 15.8 被移出 / 家庭解散后的处理

- 被移出成员或家庭已解散的成员打开小程序 → 全屏说明页「你已不在该家庭」+「回到我的个人空间」按钮
- 数据归属（v1 简化）：加入家庭后个人空间数据合并进家庭空间；退出 / 被移出 / 解散后**不拆分**，仅失去家庭数据访问，回到个人空间可见自己加入前的自有数据

## 16. 非功能需求

| 项 | 要求 |
|---|---|
| 首屏启动 | 冷启动到首页可交互 ≤ 2s（首页数据合并为 1 次云函数调用） |
| 图片 | 上传前压缩 ≤500KB；列表页用缩略图（image 组件 mode + 懒加载） |
| 兼容性 | 基础库 ≥ 2.32.0；iOS/Android 微信最新两个大版本 |
| 数据量假设 | 单用户 10 宠 × 每宠 1000 条记录内，列表/图表流畅 |
| 隐私 | 不出隐私协议之外的任何数据；类目「工具 > 效率」；无 UGC，无需内容安全审核接口（用户自己看自己的数据） |
| 合规底线 | 症状自查/喂食计算等页面均需带固定文案「仅供参考，不能替代兽医诊疗」 |

## 17. 埋点与核心指标

**关键埋点：** 首页曝光、添加宠物成功、各类型记录提交、提醒完成率、备份使用、工具箱使用。

**北极星指标：** 周活跃记录用户数（每周至少提交 1 条记录的用户数）。

**健康指标：** 次日留存、7 日留存、提醒完成率（目标 ≥60%）、人均宠物数、记录类型分布。
