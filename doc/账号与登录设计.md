# 毛球档案袋 · 账号与登录设计（免登录页 · 头像昵称自主填写）

> 版本 v1.0 · 补充模块：身份与账号体系
> 依据：微信官方《用户信息》能力（基础库 2.21.2 起）+ 小程序审核「未登录可体验」规范
> 关联：PRD §4.6（families）/ §5.4（权限与隐私）/ §15.5（成员昵称）；UI 原型 `doc/app/index.html`

## 1. 核心结论

**本项目不设登录页、不做「登录墙」。** 身份识别完全依赖微信云开发静默注入的 `openid`（`wx-server-sdk` 的 `cloud.getWXContext().OPENID`），用户打开小程序即可使用全部核心功能。

「头像与昵称」不是登录凭据，而是**可选的资料补全**：默认以系统生成的占位身份（毛球头像 + 「毛球家长」昵称）即可正常使用；用户**主动**补全后，家庭成员列表、记录归属（`createdByName`）、邀请落地页「XX 邀请你」等处展示更友好。

> 审核合规：核心功能不以提供头像昵称为前提；头像昵称仅在用户主动触发时收集（`chooseAvatar` / `nickname` input），由微信侧做内容安全检测，开发者不强制、不弹窗索取。

## 2. 设计原则

1. **零登录墙**：所有读写功能（建档/记录/提醒/家庭共享）在未补全资料前完整可用。
2. **用户主动触发**：头像用 `button open-type="chooseAvatar"`（用户点击后微信调起选头像），昵称用 `input type="nickname"`（聚焦时键盘上方可选微信昵称）。两者均**不可由代码主动调起**。
3. **静默降级**：未补全时展示默认头像（毛球 paw 素描）+ 默认昵称；家庭昵称缺省再兜底为「家庭成员」。
4. **隐私最小化**：只存「头像 URL + 昵称」两个字段；头像临时路径即时上传云存储转永久 URL，不落本地。
5. **零 emoji 红线**：头像占位用矢量 paw 素描（`components/icon/icons.js` 的 `sketch('pawPen'/'framePaw')`），不用 emoji 占位。

## 3. 身份与资料模型

### 3.1 新增 / 扩展字段

| 集合 | 字段 | 类型 | 说明 |
|---|---|---|---|
| `settings` | `nickName` | string | 全局微信昵称（默认昵称的来源） |
| `settings` | `avatarUrl` | string | 全局头像（云存储永久 URL） |
| `settings` | `familyNick` | string | 当前家庭空间内的「家庭内称呼」（优先于 nickName 展示） |
| `families.members[]` | `nickname` | string | 入空间时快照 nickName（成员只读，成员本人经 familyNick 覆盖展示） |
| `families.members[]` | `avatar` | string | 入空间时快照 avatarUrl |

> 兼容现状：现 `families.members[]` 已有 `nickname/avatar` 字段，`settings` 需补 `nickName/avatarUrl/familyNick`（`schema.js` 白名单增补）。

### 3.2 昵称展示优先级（家庭内）

```
familyNick（本人自定义） > nickName（微信昵称） > 「家庭成员」
```

- 记录归属 `createdByName`、成员列表、邀请页「XX 邀请你」、提醒完成「XX 已完成」均按此优先级取显示名。

## 4. 流程与交互

### 4.1 首次进入（无感）

```
打开小程序 → 云端 resolveFamily(openid)
  └─ 无 settings → 创建 settings（theme=auto, nickName='', avatarUrl=''）
  └─ 无家庭 → 创建个人空间，成员快照 nickname='毛球家长', avatar=''（占位）
```
未补全时：首页/我的/成员页头像显示毛球素描占位，昵称显示「毛球家长」，**全程无弹窗**。

### 4.2 补全资料（主动）

入口：
- **我的页**头卡（默认头像 + 「补全头像昵称，让家人认出你」副标题）→ 点击进入编辑态；
- **家庭成员页**本人行（头像 + 「设置我的资料」）→ 同入口。

编辑方式（就地编辑，非独立登录页）：
1. 点头像区 → `chooseAvatar` 选微信头像（或继续用默认）；
2. 点昵称输入框 → `input type="nickname"`，键盘上方可选微信昵称或手动输入；
3. 保存 → 头像临时路径上传云存储 → 写 `settings.nickName/avatarUrl` → 同步当前空间 `members[].nickname/avatar` 快照；
4. 可选：填「家庭内称呼」→ 写 `settings.familyNick`。

### 4.3 家庭协作展示

- 成员页：每行「头像 + 显示名（按 §3.2 优先级）+ 角色 + 加入时间」；本人行右侧「编辑资料」chevron。
- 邀请落地页：顶部「{创建者显示名} 邀请你加入家庭空间」（现原型写死「爸爸」，改为动态显示名）。
- 记录/提醒/账单：`createdByName` / `completedByName` 显示显示名。

## 5. UI 原型变更点（对齐 `doc/app/index.html`）

1. **我的页头卡**：默认态改为「毛球头像占位 + 昵称『毛球家长』+ 副标题『补全头像昵称，让家人认出你 ›』」，可点入资料编辑。
2. **家庭成员页**：本人行末尾加「编辑资料」入口；其余成员只读。
3. **资料编辑弹层（sheet）**：头像区（chooseAvatar）+ 昵称输入（nickname）+ 家庭内称呼（普通 input）+ 保存按钮。
4. **邀请落地页**：顶部小字改为「{动态显示名} 邀请你加入家庭空间」。
5. **头像占位组件**：统一用 paw 素描 data-URI（120×120 视口），背景沿用 `.a1-.a4` 柔和底色。

## 6. 审核与合规要点

- **未登录可用**：核心功能全程无登录门槛（满足）。
- **头像昵称非强制**：仅用户主动触发时收集，拒绝/跳过不影响任何功能。
- **内容安全**：头像经 `mediaCheckAsync`、昵称失焦检测，未通过不触发回调/清空输入（微信侧保障）。
- **隐私协议**：在「用户隐私保护指引」中声明「头像昵称用于家庭成员识别与记录归属展示，不用于其他用途，可随时删除」。

## 7. 与现有实现的衔接（改动清单）

| 层 | 改动 |
|---|---|
| `schema.js` | settings 白名单增 `nickName/avatarUrl/familyNick` |
| `db.js resolveFamily` | 建个人空间时成员快照 `nickname='毛球家长'`（占位） |
| `family.js` | `join` 时取 settings 的 nickName/avatarUrl 写入成员快照；`removeMember/dissolve` 不变 |
| `settings.js` | `get` 返回 nickName/avatarUrl/familyNick；`update` 支持写入 |
| 新增 `services/user.js` | `getProfile()` / `saveProfile({nickName, avatarUrl, familyNick})`（上传头像 → settings.update → 同步家庭快照） |
| `components/user-avatar` | 新组件：有 avatarUrl 显示图片，否则显示 paw 素描占位 |
| `pages/mine` | 头卡改为资料卡，点击进入编辑 sheet |
| `pages/members` | 本人行加「编辑资料」；展示名按优先级 |
| `pages/invite` | 顶部显示名动态化 |

## 8. 验收标准

- 未补全资料：打开即用，建档/记录/提醒/家庭共享完整可用，无登录弹窗。
- 补全资料：chooseAvatar/nickname 主动触发 → 保存后成员页/记录归属/邀请页显示名更新。
- 默认态：头像为 paw 素描占位、昵称「毛球家长」，零 emoji。
- 家庭昵称：本人填「家庭内称呼」后，本空间内优先展示。
- 审核：隐私协议声明、内容安全由微信侧保障、无强制授权。
