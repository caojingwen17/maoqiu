## 1. 首页（宠物卡片墙）

**用户路径**：每天打开的第一屏。3 秒内要回答三个问题：今天要做什么 / 毛孩子最近怎么样 / 怎么快速记一笔。

| # | 级别 | 问题 | 优化方案 |
|---|---|---|---|
| 1.1 | 🔴 | **新用户首次进入断档**：空状态只有「添加第一只毛孩子」，添加完就完了 | 添加成功后的成功页改为三选引导卡（可全跳过）：①「补全生日」→ 档案编辑生日行聚焦（有生日才有年龄、纪念日提醒）②「记第一条体重」→ 直达体重表单 ③「开启微信提醒」→ 说明文案 + 授权。全部跳过则回首页，引导条缩为卡片墙顶部一条可关闭的轻提示，填完一项消一项 |
| 1.2 | 🟡 | **首屏信息过载**：大标题 + 铃铛 + 成员头像组独占一行 + 待办卡 + 统计条 + 卡片网格，单屏用户要看 6 个信息区 | 成员头像组从独立行压缩进大标题行（标题左侧小头像组，点击进成员页）；铃铛与 Tab「提醒」入口重复——保留铃铛但**只作为红点镜像**（有待办时红点，点击直接落提醒 Tab），不再单独 push 页面 |
| 1.3 | 🟡 | **待办「完成」按钮热区过小**（原型 28px 高），且与 PRD 的「右滑完成/延后」两套手势并存，用户不知道该用哪个 | 统一主操作：**点击待办行 → 底部弹层**（同时记一笔 / 仅完成 / 延后 3 天），三选项一屏说清；右滑保留为快捷手势（完成/延后），与弹层等价。按钮撤掉，行即热区 |
| 1.4 | 🟡 | 「本周打卡」卡片点击无落点（打卡没有独立模块页） | 点击跳统计页并锚定到打卡热力卡 |
| 1.5 | 🟡 | 逾期待办在首页只有文字红，**多宠家庭多条逾期时优先级不明** | 待办排序：逾期 > 今天 > 未来 7 天，各组内按到期时间升序；逾期超过 3 天的额外显示「已逾期 N 天」加重色 |
| 1.6 | 🔵 | 单宠家庭的「单列大卡」在原型未体现；下拉刷新、骨架屏只有规范没有演示 | 原型补单宠布局快照；骨架屏在审查附录给规格即可，不占原型页面 |
| 1.7 | 🔵 | 宠物卡右上角「+」热区与整卡跳转相邻，误触风险 | 「+」热区 ≥44px 且与卡片点击区间留 8px 间隔，原型已符合，写入规范防止回归 |

**闭环检查**：✅ 添加宠物 → 记一笔 → 待办完成 → 跳详情/提醒/统计，全部有落点（修正后）。

|---|---|---|---|
| 5.1 | 🟡 | 「保存并再记一条」出现在所有表单，但疫苗/手术/就医这种一年几次的场景没有意义，稀释界面 | 只在**日频类型**显示：喂食 / 体重 / 花销 / 便便 / 饮水 / 零食 / 遛狗 / 日常；低频类型只保留「保存」 |

| 5.4 | 🔴 | **驱虫库存为 0 的闭环断裂**：PRD 说药品行标红「库存不足，点我补货」，但「点我」跳去哪、补完回不回来，没有定义；原型只有「剩 2 支」正常态 | 定义：点击红色药品行 → 入库表单（预填物品名/分类/linkType，返回后表单数据保留）→ 保存入库回到驱虫表单，药品行刷新为新余量。原型补这个红色态快照 |

| 5.6 | 🟡 | 就医表单填了费用后，PRD 说「提示同时记一笔花销」，原型没有 | 结果卡加次级按钮「同步记一笔花销 ¥380」→ 跳花销表单预填金额与分类=医疗，保存后两笔记录互相关联（note 自动带「关联就医记录」） |
| 5.7 | 🟡 | 花销表单分类原型 7 项 vs PRD 9 项（缺寄养/保险） | 以 PRD 9 项为准修正原型 |

## 16. 审查结论汇总

- 🔴 闭环断裂 **10 处**：G1/G2/G3/G4（全局）、5.4（驱虫补货）、7.4（补催对象）、8.1（统计筛选）、9.1（入库表单）、11.1（工具箱断链）、12.1（设置缺失）、14.1（邀请落地页）、15（被移出态）——**全部已在 PRD v1.1 与原型 v2 中修复**。
- 🟡 体验损伤 **21 处**：以「少打断、给后悔药、每步有落点」三原则修复。
- 🔵 打磨项 **12 处**：写入规范防回归，不阻塞开发。

**三大设计决策（审查后新增，已回写 PRD）：**

1. **结果卡替代 toast**：低频高价值记录（疫苗/驱虫/就医/手术/用药）保存后给半屏结果卡，承载「下次提醒」「修改周期」「同步记账」等后续动作；日频记录维持轻 toast。
2. **引导可关闭、可补做**：所有引导（授权、补全档案）遵循「出现 → 可关 → 降级为设置行 → 限时复现 ≤3 次」，绝不硬阻断。
3. **危险操作分级防护**：删除记录 = 普通确认；删除宠物 / 解散空间 = 输入名称确认；恢复备份 = 自动先备份再给确认。
